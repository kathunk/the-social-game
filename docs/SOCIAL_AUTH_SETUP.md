# Social Authentication Setup

This document explains how to set up social authentication with Google, Apple, and Discord for your Laravel application.

## Required Environment Variables

Add the following environment variables to your `.env` file:

```env
# Google OAuth
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret

# Apple OAuth
APPLE_CLIENT_ID=your_apple_client_id
APPLE_CLIENT_SECRET=your_apple_client_secret

# Discord OAuth
DISCORD_CLIENT_ID=your_discord_client_id
DISCORD_CLIENT_SECRET=your_discord_client_secret
```

## Provider Setup Instructions

### Google OAuth Setup

1. Go to the [Google Cloud Console](https://console.cloud.google.com/)
2. Create a new project or select an existing one
3. Enable the Google+ API
4. Go to "Credentials" → "Create Credentials" → "OAuth 2.0 Client IDs"
5. Configure the OAuth consent screen
6. Set authorized redirect URIs to: `https://yourdomain.com/auth/google/callback`
7. Copy the Client ID and Client Secret to your `.env` file

### Apple Sign In Setup

1. Go to [Apple Developer Console](https://developer.apple.com/)
2. Navigate to "Certificates, Identifiers & Profiles"
3. Create a new App ID or modify existing one
4. Enable "Sign In with Apple" capability
5. Create a Service ID for web authentication
6. Configure domains and redirect URLs: `https://yourdomain.com/auth/apple/callback`
7. Create a private key and download it
8. Use the Service ID as APPLE_CLIENT_ID
9. Generate a client secret JWT using your private key as APPLE_CLIENT_SECRET

### Discord OAuth Setup

1. Go to [Discord Developer Portal](https://discord.com/developers/applications)
2. Create a new application
3. Go to "OAuth2" section
4. Add redirect URI: `https://yourdomain.com/auth/discord/callback`
5. Copy the Client ID and Client Secret to your `.env` file

## Testing

For local development, make sure to:

1. Use `http://localhost:8000` or your local domain
2. Update redirect URIs in each provider's settings to match your local environment
3. For Apple, you may need to use a public domain with HTTPS for testing

## Security Notes

- Never commit your client secrets to version control
- Use different OAuth applications for development, staging, and production
- Regularly rotate your client secrets
- Review and limit the scopes requested from each provider

## Troubleshooting

### Common Issues

1. **Invalid redirect URI**: Ensure the redirect URI in your provider settings exactly matches the one generated by Laravel
2. **SSL required**: Some providers (especially Apple) require HTTPS even in development
3. **Email not provided**: Some users might not have public emails on their social accounts - the application handles this gracefully

### Error Handling

The application includes error handling for:
- Authentication failures
- Network timeouts
- Invalid or expired tokens
- Missing email addresses
- Account linking conflicts

If you encounter issues, check your application logs and verify your provider configurations.
